
# 24×7 live deployment

## What "always live" means
The code must run on a computer/server that is powered on and connected to the internet continuously.
Windows Task Scheduler is suitable only while your PC is awake and available.

For a real always-on setup, deploy the project to an always-on Linux VM such as:
- AWS EC2
- Microsoft Azure Virtual Machine
- Google Compute Engine
- an institution/company Linux server

The application itself is provider-neutral.

## Recommended production process
Run `python scheduler.py` continuously as a service.

That single process schedules:
- Daily full optimization + email at 08:00 Asia/Kolkata
- Hourly weather/news disruption check at minute 05
- Immediate re-optimization + alert email when thresholds are crossed

## Linux VM setup
1. Provision an Ubuntu Linux VM with outbound internet access.
2. Copy the `coal_agentic_or` folder to `/opt/coal_agentic_or`.
3. Create a dedicated user named `agenticor`.
4. Create `/opt/coal_agentic_or/.env` with SMTP credentials.
5. Create the virtual environment and install requirements:
   `python3 -m venv .venv`
   `.venv/bin/pip install -r requirements.txt`
6. Test:
   `.venv/bin/python test_web.py`
   `.venv/bin/python test_email.py`
   `.venv/bin/python daily_once.py`
7. Copy `deploy/agentic-or.service` to `/etc/systemd/system/agentic-or.service`.
8. Enable:
   `sudo systemctl daemon-reload`
   `sudo systemctl enable --now agentic-or`
9. Check:
   `sudo systemctl status agentic-or`
   `journalctl -u agentic-or -f`

Because `Restart=always`, Linux automatically restarts the scheduler if the Python process crashes or the VM reboots.

## Docker option
A Dockerfile is included.
Build:
`docker build -t agentic-or .`

Run:
`docker run -d --restart unless-stopped --env-file .env -v "$(pwd)/outputs:/app/outputs" -v "$(pwd)/state:/app/state" --name agentic-or agentic-or`

The host/VM still needs to remain powered on.

## Important
The package is not automatically hosted by downloading it. The included deployment files make it ready to host, but you still need to provision a VM/container host and place your `.env` credentials there.

## Optional always-on dashboard
The scheduler and dashboard are separate processes. Keep `agentic-or.service` running for the 24x7 monitoring loop, and optionally run the Streamlit dashboard as a second service.

1. Copy `deploy/agentic-or-dashboard.service` to `/etc/systemd/system/agentic-or-dashboard.service`.
2. Enable it:
   `sudo systemctl daemon-reload`
   `sudo systemctl enable --now agentic-or-dashboard`
3. Check it:
   `sudo systemctl status agentic-or-dashboard`
4. The default Streamlit port is `8501`. Restrict access with your VM firewall/reverse proxy rather than exposing an unauthenticated dashboard publicly.

The dashboard reads the same shared `outputs/` directory generated by the scheduler. Its live-refresh button also writes a separate timestamped `dashboard-live` run.
